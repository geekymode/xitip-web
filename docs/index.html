About

This tool checks whether a statement about the entropies of random variables is a theorem: whether it holds for every joint probability distribution of those variables. If it does, it shows a proof; if it cannot prove it, it says what assumptions about the variables would make it provable.

The quantities

For random variables X, Y, Z, the entropy H(X) measures the uncertainty in X, in bits; H(X,Y) is the entropy of the pair taken together. The conditional entropy H(X|Y) = H(X,Y) − H(Y) is the uncertainty left in X once Y is known. The mutual information I(X;Y) = H(X) + H(Y) − H(X,Y) is how much knowing one tells you about the other, and the conditional mutual information I(X;Y|Z) is the same once Z is known. Every one of these is a linear combination of joint entropies, so an information inequality such as I(X;Y|Z) ≤ I(X;Y) is a linear inequality in the joint entropies of the subsets of the variables.

Shannon-type inequalities

Some inequalities hold for every distribution: entropy, conditional entropy, mutual information and conditional mutual information are never negative. These are the basic inequalities, and an inequality that follows from them by adding non-negative multiples is called Shannon-type. Most inequalities used in information theory are of this kind: subadditivity H(X,Y) ≤ H(X) + H(Y), the data processing inequality for a Markov chain X→Y→Z, and so on. Every basic inequality is in turn a sum of elemental ones, H(Xi | all the others) ≥ 0 and I(Xi;Xj|XK) ≥ 0, of which there are n + C(n,2)·2n−2 for n variables.

How a statement is checked

Each joint entropy becomes an unknown of a linear program, one for every non-empty subset of the variables, and the elemental inequalities and your constraints become its constraints. The program minimises the left-hand side minus the right-hand side of your statement. If the minimum is not negative, the statement follows from the basic inequalities and is TRUE; the multipliers of the linear program's dual solution then say exactly which elemental inequalities, each with what weight, add up to it, and that sum is the proof shown. The proof is checked by adding it back up before it is printed.

What FALSE means

FALSE means the statement does not follow from the basic inequalities and the constraints. The linear program has found values of the joint entropies that satisfy all of them and violate the statement. For up to three variables and no constraints, such values can always be approached by actual distributions, so FALSE means the statement really fails for some distribution. From four variables on, there are true inequalities that are not Shannon-type, the first found by Zhang and Yeung: 2 I(C;D) ≤ I(A;B) + I(A;C,D) + 3 I(C;D|A) + I(C;D|B). The tool reports such an inequality as FALSE, because no Shannon-type proof of it exists. So from four variables on, read FALSE as “not provable with Shannon-type reasoning”, not as “false”.

Constraints

Lines after the first state what may be assumed: equalities or inequalities among the same quantities, or the structural shorthands X/Y/Z (a Markov chain: X and Z are independent given Y), X.Y.Z (mutual independence) and X:Y (X is a function of Y). Each is turned into the linear relations it implies, so the statement is checked over the distributions that meet them.

Suggested conditions

When a statement is not provable, the tool searches for the smallest sets of assumptions under which it would be. Each candidate assumption sets one elemental quantity to zero, which reads as a condition you might state about a model: two variables are independent, conditionally independent given others, or one is a function of the rest. Single assumptions are tried first, then pairs, and a set is listed only if no smaller set inside it already works. A counterexample prunes the search, since setting a quantity to zero cannot help if it is already zero there.

What it is for

Information inequalities are the working tools of converse proofs: showing that no code can do better than a stated rate in channel coding, source coding, network coding, secret sharing or distributed storage. Checking them by hand is slow and error-prone once there are more than a few variables. This tool checks such steps mechanically, shows the chain of basic inequalities behind each one, and helps find the independence or Markov assumptions a step silently relies on.

Limits

The linear program has 2n − 1 unknowns and about n22n/8 constraints, so the work grows quickly with the number of variables n: up to about 8 is quick, and beyond 10 is impractical. The prover is compiled to WebAssembly and runs in this page, on your computer; nothing you type is sent to a server.

Background

The theoretical foundation of this kind of checker was developed by Raymond W. Yeung, who showed that every information inequality is a linear inequality in the joint entropies, and that whether it is Shannon-type can be decided by linear programming (R. W. Yeung, “A framework for linear information inequalities,” IEEE Transactions on Information Theory, 1997).

This tool is built on, and extends, two earlier provers based on that framework: ITIP, by R. W. Yeung and Ying-On Yan at the Chinese University of Hong Kong, and Xitip, by R. Pulikkoonattu, E. Perron and S. Diggavi at EPFL.
